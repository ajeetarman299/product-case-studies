# PRD template

## Summary
One paragraph: what we are building, for whom, and the outcome we expect.

## Problem and users
- Who has the problem, and how often.
- What they do today, and what it costs them.

## Goals and non-goals
- **Goals:** the outcomes this release commits to.
- **Non-goals:** what is deliberately out of scope.

## Success metrics
| Metric | Today | Target | How it is measured |
|---|---|---|---|

## User flow
The flow as the user sees it, screen by screen. Named by the page or screen, never by the code file.

## Requirements
Numbered, one behaviour each, each one testable.

## Acceptance criteria
Given / When / Then for each requirement. A requirement without one is not ready to build.

## Edge cases and permissions
Empty states, errors, limits, and who can see or do what.

## Rollout
Phasing, flags, and the sign-off gate before production.

## Open questions
Each with an owner and a date.
